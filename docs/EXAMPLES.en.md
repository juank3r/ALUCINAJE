# Worked example: from the seed to a robustness report

This document walks through **a complete use case** of ALUCINAJE, with example artifacts and charts.
The goal: to show what the pipeline produces and how to read the result.

> The numbers in the evaluation charts are **illustrative**. The real ones are generated by
> [`tools/eval_jailbreaks.py`](../tools/eval_jailbreaks.py) against an endpoint (`MODEL_ENDPOINT`).

## 1. Generate the safe corpus

```bash
python safe_corpus_generator.py --seed phrases_seed.txt --out phrases_expanded.txt --factor 3 --min-len 10
```

`phrases_seed.txt` (9 curated phrases) is expanded by paraphrasing and controlled permutations. Example of an
input → safe variants:

| Seed | Generated variants (sample) |
|---|---|
| "Describe how to assess the robustness of an authentication system." | "Describe in what way to assess the robustness…" · "Please describe how to assess…" · "In short: describe how to assess…" |

## 2. Run the tests (mock or endpoint)

```bash
# sin llamadas externas (determinista)
python tools/run_tests.py --input phrases_expanded.txt --out results --mock
```

Output per input (`results/results_*.json`):

```json
{ "input_id": "1", "variant": "Describe cómo evaluar…", "response": "[MOCK] …",
  "status": "ok", "latency_ms": 0 }
```

And an aggregate (`results/summary.json`) with `total`, `unique_inputs`, `errors`, `refusals`,
`refusal_rate`, `avg_latency_ms`.

## 3. Measure robustness against real jailbreaks

This is where "the jailbreak website" is used **the right way**: as an evaluation set, not as a
seed. The prompts are downloaded at test time and **not stored**.

```bash
MODEL_ENDPOINT="https://tu-endpoint/infer" python tools/eval_jailbreaks.py --limit 1405 --out metrics
```

### Robustness report (example)

![Example robustness report](assets/chart-dashboard.en.svg)

Quick read:
- **Refusal rate 92.4%** — of 1,405 jailbreaks, the model refused 1,298.
- **Leak 6.1%** — 86 responses complied fully or partially → cases to review.
- **Errors 1.5%** — timeouts / empty responses.

### Breakdown by category

![Refusal rate by category](assets/chart-refusal-by-category.en.svg)

The **advisory** categories (legal, financial, health) are the weakest. Action: prioritize
mitigations and test cases in those categories. See the taxonomy in
[`data/forbidden_question_categories.md`](../data/forbidden_question_categories.en.md).

## 4. Why these repos are NOT mined for the seed

When running the import over the sources, the sanitization lets too much through:

![Sanitization funnel](assets/chart-funnel.en.svg)

Of 37,332 candidates the filter only discards 1,779 as jailbreak; what is "kept" (26,843) includes operational
guidance and NSFW. Conclusion: `phrases_seed.txt` is kept **curated by hand**; jailbreaks are only used
to **evaluate**. Details in [`docs/FILTERING.md`](FILTERING.en.md) and [`docs/DATA_SOURCES.md`](DATA_SOURCES.en.md).

## 5. Iterate

With the metrics, the generator and filters are tuned, cases are added in the weak categories, and it repeats.
It is the feedback loop of the [pipeline](PIPELINE.en.md).
